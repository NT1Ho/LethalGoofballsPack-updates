# Crew Compatibility 1.0.0 · V81 本地验收

基线为正式 V2.1.0。源文件构建命令为 `dotnet build CrewCompatibility.csproj -c Release -p:GameDir="<V81 游戏目录>"`。结果放在游戏的 BepInEx/plugins/NT1Ho-CrewCompatibility/CrewCompatibility.dll。复活、语音和目标识别需要联机各端安装，进房队列修复在房主端生效。受测组合为 MoreCompany 1.14.0、LobbyControl 2.6.0、TalkingHeads 1.0.0、ReviveCompany_Patched 发行包 1.6.0（运行时自报 1.4.0）。改动针对这些版本的实际方法。

## 真实故障证据

- 房主原始事件中有 118 次未定义的扩员尸体标签、25 次非法销毁联网尸体的报错、72 次重复复活已存活玩家，以及 95 条未能配对语音播放对象的 B 类日志。这些计数不能当作受影响的独立玩家数。NoDeathDespawn 的目标方法是回合结束时的物品回收。
- 复活 MOD 先对准尸体，按键结束时却从全场按距离另选一个，清理时再按复活者传送后的位置选一次。它会销毁尸体模型，而 V81 正将网络抓取对象挂在模型的骨骼下。它也在玩家仍为死亡状态时更新整局语音，语音组件未就绪时可提前返回，跳过受害者退出观战。TalkingHeads 在停止说话时重新查找可能已消失的骨骼，清理多个失效对象时按正序删索引，两种异常在现场均有堆栈。
- 房主六次队列超时均只缺 SyncAllPlayerLevels。V81 客户端在本地等级尚未载入时可以跳过这次 RPC。房主另一次回传饰品表时 NamedMessage 序列化需 1282 字节、只余 1280 字节。两个故障分开处理。
- 补充客户端报告中，08:51:33 UTC 启动的一份进入了同一哈希房间，客户端 36 进入轨道并继续活动；房主在 08:52:57 因缺等级检查点断开 37。两机时钟存在偏移。成功加入者观察到了另一人的断线，不能从这个视角推定离开者本机出现过哪种异常。两端共有的 97 枚插件 DLL 哈希相同。另两份补充报告只到离线菜单。其中一份启动不久便中断。
- 房主多加载两枚未受正式清单管理的 Universal Wrench 存档诊断/槽位准备 DLL。准备器受启动参数和槽位条件约束；现场未见其触发存档准备的证据。两枚已在本机核对哈希后隔离。私人报告、角色名、Steam 标识和截图留在本地。

## 修复与复查

- 对准的尸体就是复活目标。房主只撤销与该玩家绑定的抓取对象，正常网络撤销负责客户端清理；玩家搬着尸体时保留普通丢弃路径。丢失局部尸体引用时使用已算出的复活位置。忽略重复的已存活目标；恢复本地控制和观战后再刷新语音。TalkingHeads 停止事件按已有语音状态解绑，失效列表倒序清理。
- V81 只定义原生四人尸体标签。额外槽位保留预制体通用标签；移动物理区依据碰到的尸体骨骼查实际槽位。隔离房主上使用原生尸体生成方法创建槽位 4 的夹具，得到 11 个骨骼；复活其他玩家后该尸体仍在；向物理区交付实际 spine.002 碰撞器时，槽位 4 正确归属。此项使用扩员槽位夹具。
- 实际 Windows V81 房主与独立 LAN 客户端，两个方向分别执行原生死亡和复活 MOD 的请求/处理。两端观察到相同编号的可搬运网络尸体。复活后两端均回到生存、受控状态，对方模型启用且无强制剔除，远端语音播放对象存在、音量 1、未静音。死亡时存活队友听到的死亡玩家音量为 0。两端未再记录非法销毁。真实玩家麦克风、三人以上实时通话，以及原局有人只看不见某一队友的客户端状态仍未验证。
- 只在原进房期限到达、玩家已由 NGO 连接并拥有受控角色、其他所有要求均满足时，允许缺少可选 HUD 徽章同步。保留排队、容量和真正未就绪连接的超时。双端 LAN 中故意抑制客户端的双参数等级 RPC，房主经过原 40 秒期限触发修复，原队列发出完成事件，双方继续留在房间并完成后续交互。饰品沿用 NGO 的可靠分片传输，房主和客户端完成全表请求和接收。没有同一场公网事故中离开者的本机断线堆栈。
- 恢复正式宽船 1.4.3、已有双层船 2.2.14、外梯修复 0.4.5、ShipWindows 2.11.1 的原宽船配置和 Ship Edge Reverb 1.0.0。保留 Wesley 兼容 1.0.3，统一音区规则独立生效。Galetry 原种子双端降落，客户端外梯交互后实际攀升 2.99 米，窗户模块注册五个位置。二楼原坐标稳定采样 112.5–112.7 FPS，每两秒混响处理显示 0 毫秒；舱内和平台选择了不同的音区。强制缺等级的第二次演练中，房主未在原地形脚本的时限内报告降落，随后单独回读两端均为已落地。未逐扇购买验证窗户，也未对所有存档的家具位置做检查。
- 房主日志中小黑收到 8 次 force=0 的命中。其中一次该房主最近的持有物采样是 Pencil(Clone)。在真实加载的 Wesley 道具上，Pencil 的 KnifeItem.knifeHitForce 是 0，PainfulPencil 是 1，原版 Flowerman 的初始 HP 是 5 且可死亡。KnifeItem 做近距离球扫、遮挡和命中检查，再向 IHittable 传入这项数值。Flowerman 按 force 扣血，由敌人所有者判死。现场 ECDA 记录自己跳过 Flowerman 处理；没有把四个受查 MOD 中的任何一个认定为这些零伤害的原因。保留武器数据。

## 本地累计交付

5 个组件、14 个安装文件，登记工具从 V2.1.0 正式基线生成标准 ZIP 和中文说明，回读并以不保存草稿的方式验证可导入。恢复宽船时发现管理端 2.2.1 将正式基线的历史删除误认作未发布草稿的主动删除。2.2.2 区分两者，并仅允许恢复本组件在基线删除清单中已有的 manifest.json、README.md、CHANGELOG.md。通过管理端隔离工作流和正式 1.17.1 接收端契约测试。Steam 安装后对 14 个文件逐一核对，存档哈希保持一致。此次只提交开发分支。
