# 安装、更新与回退

| 现象 | 处理 |
|---|---|
| 下载 404 | 先检查签名清单 URL 所在 Release 是否真有对应哈希附件，不能只对比文件名；运行 Check-Release |
| 版本相同仍下载 | DLL 缺失/改变或发布方同版本变更可能需要修复；.cfg 在云端未变时应保持本地值。看文件级差异，不能只看版本号 |
| 签名无效 | 停止更新；检查渠道公钥和签名用途，不能跳过验签或复用旧签名 |
| 国内连接失败 | 正式客户端优先取 COS 签名清单，文件按线路探测选择并可回退；保留具体 HTTP/阶段错误，勿用来历不明代理 |
| 下载中断、SHA 不符 | 所有文件先在 pending 下载校验，未完成不安装；重试仍校验，不保留损坏文件作为成功 |
| 安装中途文件占用 | 已写事务记录的改动会自动回滚，不能恢复则保留备份并报告；退出游戏后再试 |
| 更新器报毒 | 保留 Defender 检测名称和被拦路径，核对发布 EXE SHA，向微软提交样本复核。不要关闭实时保护或添加排除来强行运行 |
| 管理端旧草稿 | 先保存未发布变动清单，再重新载入云端。版本相同也可能已有新清单 |

## 配置与存档

仅允许管理 BepInEx/config、core、plugins、patchers、pack-info 以及三个加载器根文件。禁止替换游戏 EXE、UnityPlayer、游戏程序集和普通存档。删除必须明确列入 deletes，并且本地旧管理记录及 SHA 均匹配。

接收端 1.12.29.0 起：第一次接入时已有 .cfg 保留；缺失 .cfg 安装。之后只在发布方改变该文件的默认 SHA 时更新 .cfg，并先备份。仍是文件级替换，**不是按键合并**；新入群玩家若用旧整合包配置，应与房主核对玩法相关参数。

## 回退

更新失败自动回滚已由隔离测试验证。成功更新后，原文件在游戏根目录 `.lcpack-updater/backups/<时间>`，有 journal.json、state.old 和 old-N 映射；不要删除它们。

需要恢复上一成功版本时，先退出游戏和更新器。运行 `updater/tools/Export-Rollback.ps1 -GameDirectory <游戏根目录> -Destination <不存在的新目录>`，它只校验并重建上一版托管文件，不改游戏。检查生成的“恢复前需移出的新增文件.txt”，先备份并移出列出的新文件，再合并导出的旧文件；不要只覆盖而同时留下新旧 DLL。个人配置按备份时内容恢复；存档不在导出范围。

此工具只针对最近一份已提交且有旧状态的备份；不是任意历史版本一键降级。首次安装没有旧完整状态会明确拒绝。恢复期间不要运行在线更新器，云端当前版本仍会重新安装。全体玩家回退应由维护者选择已验证旧基线，重新签名发布并明确列出新增文件的移除，不直接删除历史云端内容。
