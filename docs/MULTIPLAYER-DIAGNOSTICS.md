# LethalGoofballsPack 多人自动诊断

开发候选包含 F8 诊断插件 0.2.0、接收端 1.18.0、Hatchet 0.2.76 和 Universal Wrench 0.2.15-dev。

## 游玩与查看

房主在发生问题时按 F8。在线且支持共享的客机自动上传限量游戏事件，并在本机保留该标记附近的窗口。截图由房主游戏生成。退出后打开接收端「故障诊断」，进入该局的「跨端事件」或 F8 节点的「关联事件」。可按来源、MOD、类别、状态、标记和联机秒数筛选，双击事件可查同一个关联编号。填写备注后「保存更改」，再导出一个 ZIP。

玩家可在接收端诊断设置停用联机诊断共享，也可在 `BepInEx/config/nt1ho.lethaldiagnostics.cfg` 将 `[General] ShareWithHost` 设置为 `false`，下次启动生效。关闭共享后仍记录本机证据。兼容房主只能获得结构化的游戏状态、MOD 清单、必要错误及有限堆栈。客机截图、聊天、语音、账号和配置值排除在协议之外。分享 ZIP 前检查房主截图和第三方错误文字。

## 传输和文件

V81 NGO 命名消息通过现有游戏房间传递。接收端读取文件。协议包含版本、房间随机 ID、临时客户端 ID、来源、无账号信息的席位、事件编号、UTC 和房间联机时间。每个客机按进程序列分批，房主写入关键日志并刷盘后确认。短时间重连同一房间时续传，房主按房间、进程标识和批次去重。更换房主时清理旧房间队列。最多 180 秒缓冲，超过限额或关闭时可出现记录缺口。

- `events-*.jsonl` 普通本机记录。普通日志每秒限量。
- `key-*.jsonl` 重要事件、接收批次、版本握手和覆盖状态。关键与普通写队列独立；两种日志各自轮转，分别保留约 32 MiB。
- `identity.json` 保存实际加载版本、依赖、来源和磁盘哈希。识别磁盘存在但未加载的 DLL。通用错误可提供排查线索，无法据此读取第三方 MOD 的私有状态。
- `incident-*.jsonl` 保存标记附近的原始上下文。统一时间轴关联同房间内标记前 60 秒、后 30 秒的事件，以联机时间为准，原始 UTC 和实际接收时间仍可查。依据原始日志与仍保留的事件窗口生成，包括迟到的批次。
- `multiplayer-timeline.jsonl` 与 `multiplayer-coverage.json` 写入导出 ZIP。保留版本、参与情况、已知丢弃、异常汇总和无法对齐的证据。未上报、主动停用、版本不兼容、断开和写入故障分别有状态。
- `evidence-manifest.json` 内含原始证据和派生文件的 SHA-256。接收端删除或恢复标记时更改备注文件。删除只影响该现场及其关联，原始记录保持可恢复。

## 第一方事件关联

Hatchet 的 `death:N` 关联死亡登记、尸体、原版目击、授权、资格等待和实际效果。攻击的物品、持有者代次、挥击序号继续沿用正式链路，并通过伤害事务关联真实扣血、控制和效果。控制台状态、授权、施加、视觉分别有相应事件。只有实际进入负重、速度和原版体力恢复分支时才记录对应血怒作用。

Universal Wrench 沿维修请求、物品及保存 ID 关联条件判断、维修耗用、设施执行、Power Heart 充能和同步、哆啦口袋、装备状态。两款 MOD 都可独立运行。可选的进程内报告接口保留在接收者缺席时的兼容性。

## 构建和安装

沿用 `updater/Build.ps1 -GameDir <隔离 V81 路径> -Dotnet <SDK>`。接收端把对应诊断 DLL 嵌入程序，使用现有正常更新路径部署到 `BepInEx/plugins/NT1Ho-LethalDiagnostics/`。修复安装会保留上一版并避免覆盖更高版本。旧接收端可查看历史诊断，但无法展开多人时间轴。统一候选通过开发分支和组件登记交付，正式签名渠道按维护者指定的版本另行发布。

开发时的测试工具单独放在隔离游戏；正式组件包里只含运行文件和说明。
