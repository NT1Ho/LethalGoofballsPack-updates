## 打包前

1. 组件验收结束时，用现有累计登记交付已验证的运行文件。同步构建来源和测试记录，并保存原交付 ZIP 与 SHA-256。
2. 在 PowerShell 7 运行 `updater/tools/Check-ComponentResults.ps1`。`Records` 指向选定版本记录，`Checkouts` 以来源仓库 URL 对应本地 Git 工作树，`Deliveries` 以组件名对应批准的 ZIP 或 DLL。传入前一候选的安装清单和 `download-sources.json`，脚本会写出新旧版本、每项运行文件哈希和实际变动。`DeliveryRoots` 可列出交付目录中较新的包，逐一核对对应的实机证据。
3. 把 `Plan.files` 中确实变化的文件和所需元数据导入原有发布中心。在发包前校对整个目标安装清单与 `Plan.files`。从实体目录构建完整 ZIP 时，`Build-Pack.ps1 -ComponentPlan` 执行同一项核对。将清单中的组件文件与隔离房主、客机安装逐项对齐后，再跑受影响的场景。
4. 通过相关实测后沿用 `AdminRelease.Run` 的签名与恢复记录。先核验 GitHub 草稿附件和 COS 下载内容，再提交正式清单。提交后从接收端和两个正式源读回版本、资源与签名。

## 本次结果

0.2.74 手斧交付中的 27 个运行文件已逐项比对。相较 0.2.63 的实际运行字节，变化为 `Hatchet.dll` 和 `Hatchet.Core.dll`。三套动画数据、模型、音效、血怒和血迹资源与验收 ZIP 相同。作者工具、GameHarness 与公司训练场只安装在隔离测试环境。玩家安装包的准星和命中反馈默认均为 `HatchetOnly`，练习场可使用其现有 `Global` 设置。

万能扳手已校验完整 ZIP 中的 11 个运行文件，包含原底包、局部显形 Shader bundle、老鸟 B5 音效及授权说明。六格修复和史莱姆组件沿用已通过验证的 V2.5.8 构建。

最终完整候选安装清单共有 1462 个路径。相对正式 V2.5 新增 2 项、替换 15 项，沿用五条历史清理记录。1.17.3 离线演练应用全部 17 项，保留旧存档字节与智能柜自定义设置，再次检查为零改动。真实 V81 双端以同一套文件复测六格、空手、原版滚轮、16 次快速切换、八轮丢弃及拾回，以及客机正常挥斧、升级备用电源和照明。双端闪光起手连续，记录两次恢复短闪与两次音源播放。

最终整包使用正式终端实际下单两次，每次扣除 500 Credits，空投船交付两个可拾取的备用电源。公司训练场两端加载相同的 40 个自研组件运行文件。原版输入下房主轻击和客机蓄力重击分别由房主结算为 1 和 4 点伤害，训练场正常恢复血量。可复用同一手斧成品的命中反馈录证和同一电源之心 Shader 的光束边缘、墙体遮挡与第三人称验收。
