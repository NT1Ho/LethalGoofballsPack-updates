# Ship Edge Reverb 1.0.1 · V81 跨星球验证

## 真实记录与文件身份

V2.1.1 房主报告有八个 F8。两个 Galetry 掉帧标记都在飞船外侧约 z=-4.6，包围盒内同时出现船体 OutsideShip (2) 和星球 WindTriggers/Cube (18)。Repress 种子 55442654 的加载标记中另有 shipWindTrigger2 与 OutsideShip。Steam 的 1.0.0 DLL 与房主加载哈希相同；报告未发现受管 DLL 哈希不匹配，未发现上轮已隔离的两枚扳手测试 DLL。单凭空间重叠无法判断代码耗时。

## 船体与环境

1.0.0 处理船上各区互抢及已离船的场景交界。新增现场是玩家仍然在船上、船体和星球各有合法更新。船外侧负责乘船状态和部分光照或音量；场景风区负责环境声，有的风区本身还能设置乘船状态。两个原生回调共用每玩家唯一的 currentAudioTrigger，彼此都会重置对方。轨道中只要未同时接触这两个区，就没有这项持续开销。

1.0.1 对重叠的船外区和场景风区让原生设置各执行一次，按玩家、区域实例和连续物理步识别重复请求。失去连续接触、换区、重新登船时允许原生更新。有效舱内区与外部风区重叠时优先保留舱内效果。沿用原生混响、音量渐变、天气逻辑及船型。没有增加 Update、全场扫描或更改渲染质量。

## Repress 加载

同一房主 ZIP 中，UTC 11:22:08 已加载 Repress 场景，11:23:14 房主地牢生成完成，11:26:53 才收到全员完成。两段 FPS 采样中位数分别约 3.1 与 1.77。11:26:56 后的短窗已回到约 182 FPS。界面仍显示进入大气层；诊断中的 orbit 字段不足以说明当时没有在加载地牢。

原始 Steam 日志在对应生成到全员完成之间记下 567 次负缩放碰撞警告。单房主隔离副本使用相同种子和 ExpandedFacility，测得导航烘焙约 82 ms，没有复现几分钟个位数 FPS。延迟第二个真实 V81 进程的生成完成 RPC，可在相同等待阶段单独对比原生回调。没有改动生成大小、碰撞体、日志等级或联机超时。

## 面具人及诊断盲点

Asteroid-13 的两具面具人来自不同种子；三个标记中 enemyDead=true 且 animState=null，两张现场均为双臂平举。真实日志有客户端命中、停止表情、原生死亡和网络死亡 RPC。诊断 0.1.1 将 Animator 引用缺失、运行控制器缺失都记为 null。八个标记的 aim 都取到了房主自己的 LineOfSight2，判断敌人时使用了 nearby 网络对象和截图。

实际 V81 房主/客户端在 Repress 和 Asteroid-13（5008746、LabFlow）分别生成并击杀原生面具人。两端都播放 MaskedPlayerDie。在 Asteroid-13 生成前额外运行过未使用资源回收。房主、客户端和 Steam 的 Mirage 重整缓存内容哈希一致。MaskFixes 停止的是雷达点动画，SellBodies 的掉落面具和死亡 RPC 在实机中可以与正常倒地同时出现。本轮没有更换敌人动画、禁用表情或修改掉落规则。尚不能确定真实会话中是哪一个调用使角色失去了有效动画状态。
## 时序和性能对照

表中取同机同一点稳定后的两个约两秒窗口。开关在隔离进程内卸载/恢复已安装 DLL 的 Harmony 前缀，计时器一直保留；FPS 是整个游戏进程的实时时钟帧率，混响列为该方法的累计耗时。生产 DLL 不含计时器或测试开关。

| V81 场景 | 禁用 → 重新启用 FPS | 每约两秒原生混响耗时 |
| --- | --- | --- |
| Repress 55442654，双端，客户端在舱门等待生成回执 | 4.5、3.6 → 38.8、38.3 | 1679、1871 ms → 0、0 ms |
| Repress 同一局落地后，房主外平台 | 115.0、112.7 → 141.9、139.5 | 327、320 ms → 0、0 ms |
| Galetry 64578889，双端，第二个 F8 位置 | 56.1、57.2 → 55.8、56.9 | 144、139 ms → 0、0 ms |

原 1.0.0 独立复现使用 Galetry 68038029 和 Repress 55442654，约两秒有 200 次跨区切换。Galetry 首个 F8 坐标的混响约 0.75 秒/两秒；首次外平台候选修复的单房主观测为 230.5–231.7 FPS、混响计时 0 ms。实际交付以上表的最终二进制为准。Galetry 第二个点测得的额外 CPU 工作消失，但总帧率没有明显改善，无法据此判定全部瓶颈已解除。

在 Repress 受控实验中，客户端有意延迟 55 秒发出生成完成 RPC；同一位置和同一等待阶段执行启用、关闭、再启用三个窗口。关闭后观察到每两秒约百次双向切换，接近整个主线程时间都在原生混响方法中。再次启用恢复正常渐变，可以继续联机、落地和跨图。原始房主在部分低帧时段身处关闭的舱内，且没有每个队友的坐标与 CPU/GPU 调用耗时，不能将原记录全部 4 分多钟唯一归因于这一对区域。碰撞警告集中于生成时，在持续低帧的部分窗口记录限流计数也不再增长。

两端均保留原版天气/音响设置；外平台现场读到 OutsideForest，回执等待期间舱内读到 SmallRoomReverb。还观察到原版 1.0.0 和候选下都存在某些瞬间舱门两个原生碰撞体均关闭的情况，此时瞬移进舱不保证立即换音区；未强制启用碰撞体。一次隔离路线请求在房间刚建立时未成功，待就绪重试；另一轮 Galetry 房主降落超过脚本时限，之后通过独立状态观测确认落地再计时。无玩家生产存档用于演练。
