# V81 实机验证 · Galetry 二楼与船尾交界

环境为 Windows 本机、正式 V2.0.0 宽船的独立游戏副本、Galetry（MusemaScene）。船模、WiderShipMod 1.4.3、2 sToRy ShIp 2.2.14、Wesley Pack Compatibility 1.0.2 与两份船配置均核对真实故障 ZIP 的文件身份。使用同一种子、隔离 ES3/Dawn 存档和原生碰撞/音区回调。位置夹具用于稳定站到指定位置，没有向正式整合包加入测试驱动。

## 性能与因果

约两秒一个采样窗。下表取稳定窗口 FPS 中位数，帧时按 1000/FPS 换算。混响列是原生 ChangeAudioReverbForPlayer 的累计耗时，0 表示小于整毫秒显示精度。

| 位置与开关条件 | 关闭 → 开启（FPS） | 帧时（ms） | 每两秒混响（ms） |
|---|---:|---:|---:|
| Galetry F8 边缘，同一进程原地切换最终 DLL 的前缀，保留官方旧补丁 | 61.0 → 175.7 | 16.39 → 5.69 | 1455 → 0 |
| 历史上梯底部，轨道闭门，隔离进程撤掉旧梯口前缀，只切换统一船上规则 | 63.5 → 247.8 | 15.75 → 4.04 | 1380 → 0 |
| Galetry 船尾地面，船、离船条带与星球风区相交，最终 DLL 同进程开关 | 124.3 → 196.1 | 8.05 → 5.10 | 757 → 0 |

F8 点原生每个物理步会在船的侧条带和二楼室外区间来回切换，单方向每两秒约 100 次。接近的另一处原始异常站位也出现同样的切换，基线约 60 FPS，船上统一规则实测约 191 FPS。旧上梯点的另一方是关闭的舱门。船尾另发现 Galetry 的风区会令只比较船内两个回调的第一版方案失效，因此加入离船后场景音区的交接规则。船尾实测角色仍在地面，最后的原生环境为 OutsideForest。以上结论针对这些站位；不同星球的所有音效、所有设备和主观听感没有逐一验收。

轨道闭门舱内原生 ShipDoorClosed 和 SmallRoomReverb 生效。站上梯口时原生 Music1/ThrusterAmbientAudio 音量读数为 0.00/0.60，回舱 Music1 恢复 1.00。落地态核对门开合、玩家离船、重新登船和离开重叠处后的正常选择。某些落地时刻原生舱门盒本身未启用；不会为了这个补丁打开它，也不能将这种情况下的门动作当作室内混响切换的证据。对面边缘一处夹具站位实际落到了下层，仅作为离开上层后的观察。

## 诊断插件 0.1.1

在未修复的 V81 游戏内，持续掉帧标记与之后通过 Unity Input System 触发的 F8 在同一异常坐标，间隔约 11.9 秒。正常参考点、修复后已稳定的边缘及同机联机对照中未观察到额外的持续掉帧误报。独立的程序报错和加载尖峰标记不计作此类误报。

监控开关各测 45 秒，在相同的已修复边缘位置、关闭垂直同步与帧率限制的单房主环境中，其他夹具与配置一致。下表记录当次结果，不推算其他硬件的固定开销。

| 条件 | 平均帧时 ms | P95 ms | P99 ms | 进程 CPU 秒 |
|---|---:|---:|---:|---:|
| 关 | 4.220 | 4.554 | 11.515 | 146 |
| 开 | 4.173 | 4.413 | 11.348 | 154 |

两窗 CPU 时间存在差异，不能把帧时小幅改善解释为诊断插件提升游戏性能。F8 成功写出 2560×1440 原生截图。强制结束该隔离游戏后，接收端恢复已经写入的记录，无效/不完整 JSONL 行为 0，保存备注并实际导出异常前后窗口及截图。正式 1.17 和本机 1.17.1 分别成功导出新版会话；1.17.1 也成功导出旧 0.1.0 的八条保留记录。多人检查使用两个 V81 进程通过 LAN 回环联机，两端分别保存了各自的 F8、位置、房主/客户端身份、相同种子和可比对的网络 tick。未验证跨公网延迟。

诊断插件由本机接收端 1.17.1 内置。正式线上接收端继续为 1.17。独立游戏修复通过管理端的标准累计变更登记，诊断插件与接收端本身不混入 MOD 更新 ZIP。

## 最终二进制与本机集成

最终 ShipEdgeReverb.dll 的 SHA-256 为 3bad64e1a128475c1f107b4e9646439ae3f6c5f588e12a2d264c790a2d1767e0。最终版本同机双端均装载在正式宽船副本中：客户端在 F8 边缘实际选择二楼室外音区，保持在船上且位于室外；交换到船尾地面后，房主和客户端分别记录 Galetry 风区、OutsideForest 和已离船状态。在 Galetry 直接传送穿过入口回舱时，登船/室内标志会更新，该时刻原生舱门碰撞盒未启用，未将此路径算作室内声学切换验收。轨道闭门原生碰撞盒启用时，出舱与回舱的音区和源音量切换已另行实测。

本机 Steam 安装副本的实际进程记录同时报告 Ship Edge Reverb 1.0.0 与 LethalGoofballs Diagnostics 0.1.1，后者 SHA-256 为 9c92568790f18d98d00d12dc6d2ae3ee11e5953124176eaea52d433c50f1e27f。接收端启动器实际交接至本机 1.17.1 缓存运行程序，游戏运行期间进入浏览流程。连续两次运行接收端的插件安装/修复逻辑后 DLL 哈希相同。升级前的本地程序、插件、配置及缓存指针已备份。本机历史诊断快捷入口改用游戏目录内的接收端，避免调用旧候选中内置的旧 DLL；手动指定其他旧版 EXE 直接执行修复仍会按旧程序自身逻辑处理。

按 Register-ModResult.ps1 登记 NT1Ho-ShipEdgeReverb-r1，生成标准累计 ZIP，在临时管理工作区导入并完成候选预检。之前的两个组件继续保留。生产 COS 整合包签名清单前后逐字节哈希相同；真实 Steam 副本完成启动与正常退出后，对照的十个原有存档/设置文件及接收端整合包状态哈希不变。
