# 更新器维护约定

管理端、接收端和整合包分别维护版本。整合包只使用维护者明确指定的版本名。先读 ADMIN-2.0.md，正式状态以验签后的公开清单和工作区基线指纹为准。

- 修改文件清单、包来源归属、展示资料或恢复流程时，明确哪一端写、哪一端读。使用 tests/Test-Admin.ps1 的隔离工作流，并传入另一端已验证的正式 EXE 做契约检查。
- 管理端单独迭代用 Build.ps1 -AdminOnly，不覆盖已发布的接收端。界面改动要检查实际运行的窗口；游戏诊断采样不在管理端职责内。
- 构建和测试均不构成授权发布。默认使用临时工作区、生成的测试密钥、模拟 HTTP 服务。生产凭据、真实草稿、玩家诊断、截图、候选对象和整包不进入源码仓库。
- 源码提交同时记录改动、相关验收与未覆盖的实际环境。保持正式包清单与接收端自更新指针分离。
