# Pack Updater 管理端 2.0

管理端产品版本为 2.0。整合包版本由维护者指定。2026-11-01 验签核对时，广州 COS 正式整合包为 V2.0.0，共 1310 个文件，GitHub 备用清单一致，接收端通道为 1.16。旧文档中的 V1.9.5 正式版与 V2.0.0 候选是较早阶段。同名的本地船型等实验内容，仍须对照清单指纹和文件 SHA 判断。

## 日常操作

1. 打开管理端 EXE。它沿用原 Windows 用户的工作区、对象缓存和加密凭据。主界面显示工作区基线及候选版本。“渠道设置 → 核对在线版本”读取签名清单，不替换草稿。“采用正式清单”才会切换基线，并保留旧草稿副本。
2. 在“整合包内容”搜索 MOD 或文件。可拖入文件、文件夹或单组件 ZIP。ZIP 需要根目录含包描述；核对发布者、安装路径和旧文件删除列表后加入候选。明确属于其他包的目标会被拒绝。上游包有不规则安装要求时，使用明确相对路径的文件或文件夹导入。
3. 替换单个目标或在文件视图编辑 CFG。候选配置按分组、键、值编辑，保留注释、BOM 和换行。只支持最多 1 MB 的 UTF-8 键值配置，其他格式请替换源文件。玩家已有 CFG 是否覆盖仍遵守接收端既有规则。
4. 在“发布中心”设置候选版本。“接收端资料”可编辑名称、用途、自研／改版、NEW、排序、颜色和历史，并使用玩家实际页面预览。“从变更生成说明”按组件生成可编辑的事实摘要，请把涉及玩法、修复和兼容性的内容写成玩家能理解的说明。已有同版本历史不会被自动覆盖。
5. “检查候选”核对路径、文件身份、明确的版本名和历史记录。内容变更需要新版本名；仅展示资料的同版本修订继续使用原专用事务。选中变更可还原到基线。整组撤销涉及登记资料时，需同时选择对应的登记文件，或恢复事前保存的草稿副本。
6. “导出候选 ZIP”保存目标清单、差异说明及去重后的变更对象；它用于本地评审。“更多 → 导出完整安装 ZIP”按清单中的游戏相对路径生成完整安装文件包。未缓存的正式对象会经过校验下载，已有同名安装包会被拒绝覆盖。
7. 正式发布有独立的确认步骤。程序按既有 COS 签名、对象上传和 GitHub 备份机制执行，再回读核对两个清单。中断后“继续未完成发布”读取持久任务。COS 已提交时跳过重复提交。出现不属于原基线或目标的指针会停止恢复，需核实外部发布；不要删除恢复文件强行继续。仍未提交、且没有运行中的展示资料事务时，可核对并解除本地任务。

密钥只在 Windows 当前用户身份下加密保存。更换 COS 上传账号沿用已存在的签名身份，新电脑需要恢复原签名身份；重新生成一套密钥不会被现有接收端接受。接收端自身发布走独立通道。诊断插件由接收端随程序安装，个人诊断文件不属于管理端候选。

## 审查和实施记录

旧管理端使用单条 WPF 工具栏处理导入、编辑和发布。组件表常用静态介绍，缺少基线差异及逐项撤销，ZIP 可能被当作普通文件，逐文件写草稿会产生半批结果。新增后移除也可能留下删除指令。GitHub 令牌没有图形设置入口，COS 完成与 GitHub 备份未完成的状态不够明确。

新版保留原工作区、包归属、SHA 对象缓存、签名、公钥、双端发布和同版本页面恢复机制。补充基线快照、批量原子提交、陈旧草稿拦截、包归属更新、只读 DLL 元数据识别与发布恢复记录。主界面按内容、接收端资料、发布中心、渠道设置拆分，使用系统浅色 WinForms 控件。内容列表按现有页面排序，必要操作随选中范围启用。新版独立构建和交付管理端，接收端安装文件无需重编译。

## 构建和同步维护

仅构建管理端：在仓库根目录执行 `./updater/Build.ps1 -AdminOnly -SkipTests -OutputDirectory ./artifacts/admin`。带验收时去掉 -SkipTests，并传入 `-CompatibilityReceiver <已正式发布的接收端 EXE>`。

默认联合构建将新生成的两个程序一起交给 tests/Test-Admin.ps1。单端改动也可对照已发布的另一端：脚本在隔离目录运行真实代码，对候选流程、模拟发布、WinForms 操作以及接收端实际读取进行检查。变更 manifest、包归属、展示资料、签名类型、下载引用或发布顺序时，应更新相应契约用例并记录对两端的影响。纯接收端界面或纯游戏行为改动无需重跑整包发布。

隔离操作：`管理端.exe --workspace "独立测试目录"`。该入口可编辑本地候选、导出和读取公开渠道；禁止正式发布和保存生产凭据。不要将测试目录指向真实工作区。

## 本版验收范围

- 28 项工作流检查。整批失败不改草稿、并发陈旧版本拒绝写入、配置格式保留、ZIP 归属和升级、跨包覆盖拒绝、完整移除、校验与缓存修复、撤销、历史生成、两种 ZIP、现有安装包保护、恢复以及仅读取 DLL 特性。
- 使用新建测试密钥和内存 HTTP 服务执行实际 COS/GitHub 发布代码。主动使备份失败，重开工作区；不同的备用指针被拒绝覆盖，正确恢复后主指针只提交一次，签名载荷与 Release 附件一致。
- 9 项管理端控件检查，包括在真实配置弹窗写回候选、历史编辑器保存、搜索和从发布中心撤销。另用正式 1.16 EXE 验签、解析清单和历史，并扫描登记后的 Sample 1.0.2 资源组件。
- 已有页面编辑及别名、排序、颜色测试 22 项通过。同版本展示资料模拟发布和中断恢复 12 项通过。
- 使用正式基线的隔离副本直接启动交付 EXE，切换四个工作区、只读核对公开渠道、捕获实际窗口并手动关闭。界面截图中的 QA-LOCAL 是演练草稿。真实管理端草稿哈希保持一致。
- 没有执行生产上传、创建 GitHub Release 或替换正式签名清单。生产服务的写权限、跨机器凭据恢复、所有第三方 ZIP 的特殊安装规则都未作线上验收。
