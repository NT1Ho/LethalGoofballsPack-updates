# Wesley V81 candidate upstream and compatibility audit

The package archive lock contains 28 recursive packages, 17 additions and 11 reused from Steam. Official latest metadata was requested via the Thunderstore experimental per-package API. Root versions were confirmed against the actual ZIP manifests. New archives were SHA-256 hashed, expanded with ZIP CRC validation, and each expanded member hashed. For reused packages archive hashes are from the pack's source inventory. The installed DLLs were hashed directly. `sha256` is the unmodified upstream member. A locally adapted member includes a separate `candidate_sha256`. GUIDs come from the selected assemblies' BepInPlugin metadata, independently of package versions. Component-only bundles have no plugin GUID.

Facto 1.2.1 explicitly depends on the standalone Decrepit Store. Neither the Facto scene nor storeinterior bundle is in the two collected main packs in these versions. Keep both additions. Existing BepInEx 5.4.2305, LethalLib 1.2.0 and private pack mods remain in place. No duplicate added plugin GUID or missing declared hard plugin GUID was found in the overlay audit. This does not prove every content mechanism works.

Progression uses upstream configuration. WesleyMoonScripts.LevelCassetteLoader server-resolves the held object's authored LevelCassetteItem. Some cassettes and gates have different actions and do not unlock a scene. QuickSell 1.1.10 filters normal batch sales by grabbable prefab name after removing the clone suffix. The installable blacklist keeps all four existing entries plus 91 confirmed Wesley prefab names, merging qa/quicksell-evidence.tsv with extra inputs corroborated by 128 serialized bundles. This is a per-install protection for ordinary batch selling. Explicit ignore-blacklist (-a), temporary exemptions, and deliberate item-by-name sale are not permission barriers. General manufacturing materials and the ordinary vanilla Apparatus are intentionally not blanket-excluded. No story item ID was renamed.

The original SnatchinBrackenFORK installation distinguishes "Floating head"/"FloatingGirlHead" and has Snatchin Floating Head=false. ECDA's runtime-generated entries enable Assimilated employee and Assimilated growth by default. Wesley's AssimilatedEmployee.KillEnemy actually creates the player's dead body and networked grabbable ragdoll. Generic death/despawn handling could conflict; this is source evidence, not a reproduced duplicate or justification for a global AI change. FairAI's existing ImmortalAffected=false is retained. Some author timers use deltaTime and others normalizedTimeOfDay. Existing day slowdown changes the latter by design. No global time or regeneration adjustments were added here.

## Reproduced candidate-specific compatibility failures

* ModDataLib 1.2.2 IL_0020 calls GetType on PluginInfo.Instance. wesley-01.log:2720 aborts the whole registration; the caught optional SoundAPI type warning one line earlier is separate. The retained small local patch filters instance-less registrations for that one scan. In wesley-03.log the skipped GUID is MW.MagicWesleyInteriors, then "Hooking up save, load and delete events..." runs. Subsequent inspection showed why the interior plugin had no instance.
* Original WesleysInteriorShenanigans.dll from Interiors 5.0.19 references eight DunGen types in Assembly-CSharp, but V81 supplies these exact types and members in DunGen.dll. wesley-03.log reports that InteriorModifier cannot instantiate. Relink-InteriorDunGen.ps1 validates the original hash, relocates only these scopes and validates that all corresponding members resolve. This retains the author's existing Citadel and Armory rules. Original and adapted hashes are both in the lock.
* Host wesley-02.log:21084 traced the Extort return failure to a destroyed Sprite.name read in the Chinese results UI, propagated through the vanilla end-of-game RPC. The compatibility patch checks Unity object liveness at name reads in the stats-box lookup/scoring only. 
* Static QA located exactly three hardcoded four-slot bounds in SpecialGhostGirl.ChoosePlayerToHaunt. HauntingPlayerSlots preserves its targeting and network outcome while using real slot counts, bounded by the stats array where applicable. This is source-confirmed, not evidence of an actual five-person run.

The final run evidence is reported by the shared central game runner. No upstream package archive, extracted C# decompilation, game DLL, or Unity bundle belongs in the source repository.

* 03 saved an officially unlocked Asteroid13Scene. On 04 rejoin the host had hidden=false/locked=false while the client had both true. Wesley default-locks campaign scenes when LLL populates content. LLL 1.7.13 SaveManager.InitializeSave restores and broadcasts once while the host opens the slot; the later join path only refreshes bundle status. The 1.0.1 compatibility module asks for a snapshot after both local content initialization and NGO connection. Only the host sends the authored campaign routes' current lock/hidden bits, only to the joining client. No command, save field or unlock event is used. Compare both peers using qa/Invoke-WesleyQA.ps1 -Op story with the same saved host and a fresh client.
* Cold join diagnostics: V81 emits LLL LobbyInitialized inside the StartOfRound.Awake prefix, before assignment of the game's singleton. A named NGO message's FastBufferReader includes the 8-byte channel hash in Length and has Position=8 on entry. Both details were verified against the installed binaries. Run 07 with the fixed, versioned handshake: host received Length=9, Position=8 for client 1, sent 52 authoritative flags, and client applied all 52. Host wesley-07.log lines 5944–5945, client wesley-07.log line 5672. These transport observations are separate from the central runner's subsequent comparison of actual route values.
